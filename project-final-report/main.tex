\begin{abstract}
SGP4, the standard propagator for the public satellite catalogue, accumulates kilometre-scale errors over multi-day predictions, dominated in low Earth orbit (LEO) by mis-estimated atmospheric drag. This project trains a machine-learning model to predict, and subtract, SGP4's error. Using two years of element sets for 246 debris objects and rocket bodies (1.38 million prediction pairs), a gradient-boosting model was compared with uncorrected SGP4 and with a physics-based ridge regression, on 39 objects and a three-month period never seen in training. The model reduced root-mean-square (RMSE) position error by 12.5\% (95\% CI 4.4--17.1\%), almost entirely by shrinking the largest drag-driven errors below 700~km; typical (median) errors were not significantly changed, and the ridge alternative gave no improvement. Ground truth is a later-issued element set, so the results measure consistency between element sets rather than true position error.

\section{Engineering Problem}\label{sec:1}
%=====================================================================

\textbf{Context.} Most tracked objects in LEO are inactive debris or spent rocket bodies. Operators of active spacecraft screen their planned trajectories against this population for close approaches, and the only position data publicly available for most of it are the US Space Force's two-line element sets (TLEs), together with the SGP4 propagator they are designed for \cite{hoots1980,vallado2006}. A TLE is not a measured position: it is a set of mean orbital elements fitted to tracking data, and SGP4 is a semi-analytic model that propagates those elements forward with simplified gravity and drag models.

\textbf{Problem.} SGP4 predictions degrade with time. In LEO the dominant error source is drag: the TLE's drag term (B*) is itself a fitted value, and atmospheric density changes with solar and geomagnetic activity that the model cannot anticipate \cite{vallado2013,picone2002}. A small error in the drag estimate produces a timing error, an object running ahead of or behind its predicted position, that grows roughly with the square of the prediction horizon. Published comparisons put TLE errors at around a kilometre near epoch, growing to several kilometres or more within days \cite{kelso2007,levit2011}.

\textbf{Why it matters.} Conjunction screening on TLEs must either use large safety margins, which raise false-alarm rates, or accept the risk of missed close approaches. Better multi-day predictions from the public catalogue would directly improve both.

\textbf{Intended use.} The solution is a correction layer applied after SGP4: given an element set and a prediction horizon, it estimates SGP4's error in radial, along-track and cross-track components and subtracts it. It needs no new tracking data, only information available at the element set's epoch, so it could run as a batch step in a catalogue-wide screening pipeline.

\textbf{Scope and its limitations.} The project is limited to non-manoeuvring objects (debris and rocket bodies) with perigee 300--2000~km and horizons up to 7~days. Active satellites, deep-space orbits (which use the separate SDP4 branch) and highly eccentric orbits are excluded. Most importantly, the reference ``truth'' for a prediction is a later-issued TLE evaluated at its own epoch. This is the only ground truth available at scale for debris, but it is itself an SGP4 fit with roughly kilometre-level error, so the project measures and corrects \emph{TLE-to-TLE inconsistency}, not true position error (Section~\ref{sec:7}).

\section{Inputs, Outputs and Data}\label{sec:2}
%=====================================================================

\subsection{Data sources and processing}

The workflow is a chain of scripts run in order (see the README), each caching its output so later stages can be re-run independently: \texttt{download.py} (object selection from the CelesTrak catalogue \cite{celestrak_satcat}, element-set history from Space-Track \cite{spacetrack}, daily space weather \cite{celestrak_sw}); \texttt{pairs.py} and \texttt{frames.py} (propagation and RTN residuals); \texttt{features.py} (model inputs, outlier flags); \texttt{models.py} and \texttt{evaluate.py} (training and evaluation); and \texttt{performance.py} (timing, profiling, feature importance).

\textbf{Object selection.} Catalogue objects were filtered to debris or rocket bodies, still in orbit, with perigee $\geq 300$~km, apogee $\leq 2000$~km and launched before the data window. Sixty were sampled at random (fixed seed) from each of five perigee bands, and the 50 per band with the most element sets (minimum 200) were kept. The result is 246 objects (198 debris, 48 rocket bodies; 46 in the 700--900~km band), with inclinations from 25$^\circ$ to 144$^\circ$. The object list is committed to the repository (\texttt{data/objects.csv}). The raw Space-Track data are not redistributed; the download script reproduces them.

\textbf{Element sets.} The window is 1~July 2024 to 1~July 2026. Of 351,010 element sets downloaded, 55,793 (16\%) shared an epoch with another record (Space-Track re-issues element sets) and were removed, keeping the most recently created; none were malformed, leaving 295,217.

\textbf{Prediction pairs.} For each element set $i$, up to five later element sets $j$ were chosen, one at random from each 1.4-day slice of the 0--7 day horizon range, so horizons are evenly covered. Element set $i$ is propagated to the epoch of $j$, and the residual is
\begin{equation}
\Delta\mathbf{r} = \mathbf{r}_{\text{SGP4}}(i \rightarrow t_j) - \mathbf{r}_{\text{SGP4}}(j \rightarrow t_j),
\end{equation}
expressed in the RTN frame of the reference state: $\hat{\mathbf{R}} = \mathbf{r}/|\mathbf{r}|$, $\hat{\mathbf{N}} = (\mathbf{r}\times\mathbf{v})/|\mathbf{r}\times\mathbf{v}|$, $\hat{\mathbf{T}} = \hat{\mathbf{N}}\times\hat{\mathbf{R}}$. The RTN frame separates the physically distinct error components: drag error appears almost entirely in the along-track ($T$) component. This produced 1,381,981 pairs with no SGP4 errors.

The data are summarised by band in Appendix~\ref{app:data}, and Figure~\ref{fig:checkpoint} shows SGP4's error growth. Along-track error dominates and grows faster than linearly, while radial and cross-track errors stay an order of magnitude smaller. This was the checkpoint used to confirm that the frame transformation and pairing were correct before any modelling.

\subsection{Outputs}

The model outputs a predicted SGP4 residual $(\Delta R, \Delta T, \Delta N)$ in km for a given element set and horizon. The corrected prediction is the SGP4 position minus this residual. The evaluation outputs are position-error statistics (median, 95th percentile, RMSE, in km) by altitude band and horizon, with bootstrap confidence intervals, saved as CSV files and figures in \texttt{reports/}. Function-level inputs and outputs are documented in the docstrings and the generated HTML documentation \todo{generate with pdoc and link}.

\subsection{Invalid, missing and unsupported inputs}

Malformed element sets (non-numeric fields, unparseable epochs, eccentricity outside $[0,1)$, non-positive mean motion) are dropped and counted, as are pairs where SGP4 returns an error code (none occurred); for duplicate epochs the most recently created record is kept. Missing history features are passed to the trees as missing values, which gradient boosting handles natively, and set to zero for ridge. Pairs above the 99.9th percentile of error within their altitude band and 1-day horizon bin (1,399) are flagged, excluded from training and kept in all evaluation. Unsupported inputs are \emph{not} rejected automatically: horizons beyond 7~days, perigees outside 300--2000~km, manoeuvring satellites and deep-space orbits lie outside the training domain, and the model will silently return predictions for them (Section~\ref{sec:7}).

\subsection{Gradient boosting}

The selected method is gradient-boosted regression trees, using scikit-learn's histogram-based implementation \cite{friedman2001,ke2017,pedregosa2011}. It extends the single decision-tree regressor of unit topic 5.2: one deep tree overfits noisy data (topic 3.2), whereas boosting adds many small trees in sequence, each correcting the errors of those before it. The model is a sum of $M$ small regression trees,
\begin{equation}
F_M(\mathbf{x}) = F_0 + \nu \sum_{m=1}^{M} h_m(\mathbf{x}),
\end{equation}
where each tree $h_m$ is fitted to the negative gradient of the loss at the current prediction and $\nu$ is the learning rate. With absolute-error loss, each tree is fitted to the sign of the current residual and its leaf values are set to medians, which makes the model robust to the heavy-tailed residuals in this data (the 99.9th percentile is 70--190 times the median in every band). Inputs are binned into 255 histogram bins, which is what makes training on 650,000 rows take under a minute.

One model is trained per RTN component. Previous work has corrected orbit predictions from public data with neural networks \cite{peng2018ann}. Gradient boosting was chosen here because the data are tabular with mixed feature types, a setting where tree ensembles generally outperform neural networks \cite{grinsztajn2022}; because the physics involves interactions (drag error depends jointly on altitude, space weather and horizon) that trees capture without being specified; because missing values need no imputation; and because inference is fast and the model can be interrogated with feature importance.

\subsection{Physical constraint: zero correction at zero horizon}

An element set has no propagation error at its own epoch, so any correction must vanish as the horizon $h \to 0$. Rather than leaving the model to learn this, it is built in: the trees learn the residual per day of horizon, $g(\mathbf{x}) \approx \Delta/\tau$, with $\tau = \max(h, 1\,\text{h})$ to avoid division by near-zero horizons, and each sample is weighted by $\tau$. Because
\begin{equation}
\sum_k \tau_k \left| \frac{\Delta_k}{\tau_k} - g(\mathbf{x}_k) \right| = \sum_k \left| \Delta_k - \tau_k\, g(\mathbf{x}_k) \right|,
\end{equation}
this still minimises absolute error in km, while the prediction $\tau g(\mathbf{x})$ shrinks to near zero at short horizons.

\subsection{Physics terms}

A constant error $\Delta\dot{n}$ in the rate of change of mean motion gives an along-track error
\begin{equation}
\Delta s(t) \approx \tfrac{1}{2}\, a\, \Delta\dot{n}\, t^2,
\end{equation}
where $a$ is the semi-major axis \cite{vallado2013}. Interaction terms built on this form (horizon$^2$, B*$\times$horizon$^2$, previous drift rate $\times$ horizon and $\times$ horizon$^2$, previous errors $\times$ horizon) are added to the inputs of both learned models, so the known growth law does not have to be rediscovered from data.

\subsection{Training, validation and test split}

Pairs from the same object are strongly correlated, so a random split, as used for independent samples in unit topic 5.6, would leak information between training and test. The split is therefore by object and by time. Objects are assigned 70/15/15\% to training, validation and test within each altitude band (168/39/39 objects). Training pairs end before 30~December 2025; validation uses the validation objects from then until 31~March 2026; the test set is the test objects from 31~March 2026 onwards. This gives 653,011 training, 33,605 validation and 30,738 test pairs. Every test result is on objects the model has never seen, in a period it has never seen.

\subsection{Settings and model development}

Hyperparameters were chosen by a random search of eight configurations on a 150,000-row training sample, scored by along-track validation MAE. The default configuration is always included. The number of trees (up to 300) is chosen by early stopping on validation error, after which the model is refitted with that count. The selected settings were learning rate 0.05, maximum 127 leaves per tree, minimum 50 samples per leaf and no L2 penalty, giving 132, 172 and 230 trees for the R, T and N components.

The model went through three iterations, each driven by a diagnosed failure (Table~\ref{tab:runs}):
\begin{enumerate}
\item \textbf{Run 1:} validation objects shared the training period. Tuning rewarded models that memorised conditions of that period, for example through the slowly varying 81-day solar flux, which effectively encodes the date. On the test period the correction made median error 22\% worse.
\item \textbf{Run 2:} validation moved to its own period between training and test. The model now beat no correction on validation, and test RMSE fell 12\%, but short-horizon errors were still inflated.
\item \textbf{Run 3 (final):} the zero-horizon constraint above was added to both learned models.
\end{enumerate}

\textbf{Assumptions.} The approach assumes that SGP4's error is partly predictable from information available at epoch, that the relationship learned from 168 objects transfers to others in the same altitude range, and that the training period's conditions resemble the deployment period's. It cannot anticipate space weather during the prediction window, which is the largest unpredictable driver of drag \cite{picone2002}.

\section{Alternative Solutions}\label{sec:4}
%=====================================================================

Two alternatives were implemented and two more were considered and rejected.

\textbf{Baseline: uncorrected SGP4.} The operational standard and the reference that any correction must beat.

\textbf{Alternative: ridge regression on physics terms.} This extends the linear least-squares regression of unit topic 5.1 by adding an L2 penalty on the coefficients, a standard control for the overfitting covered in topic 3.2: $\min_\beta \|\mathbf{y} - X\beta\|^2 + \alpha\|\beta\|^2$, on the eight horizon-proportional physics terms, with no intercept and the regularisation strength $\alpha$ chosen on validation from $10^0$ to $10^4$. It tests whether the known drag-growth law, with coefficients fitted from data, is enough on its own. It is fast, has five kilobytes of parameters and is fully interpretable.

\textbf{Considered and not implemented.} A numerical propagator integrating gravity, J2 and drag with a Runge--Kutta method (unit topic 7.4), started from SGP4's position and velocity at epoch, would replace SGP4 rather than correct it. It was not implemented within the project timeline, and it would face the same dominant error source, since the drag coefficient must still be estimated from the element set; it remains a worthwhile numerical baseline for future work. A physics-informed neural network (topic 10.3, \cite{raissi2019}) needs a governing equation to enforce, and the difference between two SGP4 fits has none; the useful part of that idea, encoding known physics, is captured instead by the physics terms and the zero-horizon constraint.

\section{Validation}\label{sec:5}
%=====================================================================

\subsection{What was validated and how}

\textbf{Verification of the implementation.} 32 automated tests (pytest; summarised in Appendix~\ref{app:tests}, all passing, with full results in \texttt{reports/test\_report.html}) check the frame transformation, the element-set loader against the reference TLE parser (agreement within 1~mm over 7~days), each pair residual against an independent SGP4 computation, the absence of leakage in space weather and in the split, the zero-horizon constraint, recovery of a known relationship in synthetic data, and equivalence of the optimised and original code.
The SGP4 implementation itself is the \texttt{sgp4} library \cite{rhodes_sgp4}, which is validated by its authors against the published test cases of Vallado et al.\ \cite{vallado2006}. These cases were not re-run in this project \todo{either add a test that runs them, or keep this sentence}. Physical plausibility was checked with Figure~\ref{fig:checkpoint}.

\textbf{Validation of the model.} The model is validated against withheld data: 39 objects and a three-month period never used in training or tuning, with the later-issued element set as ground truth. Because the residuals are heavy-tailed, three statistics of 3-D position error are reported: the \emph{median} (typical error), the \emph{95th percentile} (bad cases) and the \emph{RMSE}, which is dominated by the largest errors, the ones that matter most for collision screening. Confidence intervals come from a bootstrap that resamples whole objects (500 resamples) \cite{efron1993}, since pairs from one object are not independent; this extends the regression metrics of unit topic 5.5 to correlated data. A correction is accepted as an improvement on a measure only if the whole 95\% interval lies above zero.

\textbf{Influence on model selection.} Validation data chose the hyperparameters, the number of trees and the ridge regularisation. The test set was used for the final evaluation, but test results from runs 1 and 2 were also seen before the run 3 change was made, so the test set influenced one design decision. The run 3 constraint was motivated by physics rather than tuned to the test numbers, but the final confidence intervals may be slightly optimistic as a result.

Its validation-selected regularisation was the strongest available ($\alpha = 10^4$) for the radial and along-track components, meaning the data favoured shrinking it towards no correction at all.

\subsection{Interpretation}

Permutation importance \cite{breiman2001} on the test set (Figure~\ref{fig:importance}) shows the model relies on evidence that the drag estimate is wrong: the change in B* since the previous element set, the recent along-track drift rate, the horizon, the geomagnetic Ap index, and the mean motion derivative (orbital decay rate). This matches the physics. A sudden change in the fitted B* means the drag estimate is unsettled; recent drift shows the current estimate is off; and geomagnetic storms heat the thermosphere and raise density beyond what B* assumed \cite{picone2002}.

The solar flux (F10.7) features have slightly negative importance: shuffling them makes predictions marginally better. Solar flux varies over months, so the model probably used it to identify the time period rather than to learn about drag. This was found on the test set, so the features were not changed afterwards.

This also explains where the correction helps. Below 700~km, drag dominates and its mis-estimation leaves detectable traces in the recent history, so the largest errors are partly predictable. Above 900~km drag is weak, errors flatten to a floor of a few hundred metres set by noise in the element-set fits themselves, and there is little systematic signal to learn.

\subsection{What the validation cannot establish}

\begin{itemize}
\item \textbf{True position accuracy.} The reference is another element set, so the results show the correction makes predictions more consistent with the \emph{next} TLE, not closer to the satellite's true position. Precise ephemerides (for example, laser-ranged satellites) would be needed for that.
\item \textbf{Generality across time.} The test period is a single three-month window (April--June 2026) at one phase of the solar cycle. Performance in quieter conditions, or during storms more extreme than the training data (maximum Ap 144), is unknown.
\item \textbf{Generality across objects.} With 39 test objects (7--8 per band), per-band results are uncertain, and objects outside the selected population are untested.
\end{itemize}

Gradient boosting costs 12.5 times one SGP4 call, but still processes about 200,000 predictions per second on one core; a single prediction takes 11~ms of library overhead, so a deployed system should batch. Its 534 trees hold 135,102 nodes (about 57 bytes each), and each node visit loads a record to perform one comparison, roughly one operation per 50~bytes of memory traffic. With 7.6~MB of trees, larger than a typical L2 cache, inference is bound by memory latency and branching rather than arithmetic; ridge's 0.5~$\mu$s is dominated by call overhead. Training takes about 50~s per component on 653,011 rows.

\subsection{Profiling-driven optimisation}

Following the profiling approach of unit topic 2.1, \texttt{cProfile} showed the history features dominated the pipeline: each residual was rotated into RTN with a separate call, 1,541 rotations taking 0.193~s of 0.374~s for one object. The improved version rotates all states in one array operation, with a test confirming identical results. History features ran 5.3 times faster (0.44~s to 0.08~s on 6,987 element sets), the per-object pipeline 2.4 times faster (0.374~s to 0.156~s), and function calls fell from 438,203 to 99,651, leaving no single dominant cost.

\subsection{Sensitivity}

All eight hyperparameter configurations beat no correction on validation (MAE 16.66--17.03~km against 17.82~km). Their 2.2\% spread is smaller than the gain over SGP4, so results are not sensitive to these settings. They are far more sensitive to validation design: separating validation in time from training (run 1 to run 2, Table~\ref{tab:runs}) reversed the conclusion. Altitude and horizon sensitivity are shown in Table~\ref{tab:bands} and Figure~\ref{fig:growth}, and excluding flagged outliers changes only the top band without changing which method is better. Sensitivity to the amount of training data, and training on low bands while testing on high ones, were not performed \todo{add if time allows, or keep as future work}.

\subsection{Selected design}

Gradient boosting is selected because it is the only method that reduced error on any measure, at an acceptable cost of a few microseconds per prediction; ridge is faster and smaller but cannot represent the altitude dependence of the error. The recommended deployment is batch correction below 700~km and beyond one day's horizon, a gating rule that should first be confirmed on validation data, since it was identified from test results.

\section{Limitations and Lessons Learned}\label{sec:7}
%=====================================================================

\textbf{Limitations.} Beyond those in Section~\ref{sec:5}: the correction does not improve typical error, and adds a few hundred metres at short horizons in low LEO; the test set was viewed during development; and out-of-domain inputs are not rejected. The weakest point is a manoeuvring or newly fragmented object, whose history features describe a different orbit; a production version should flag large B* jumps and fall back to uncorrected SGP4. Space weather during the prediction window cannot be known, which bounds the achievable improvement.

\textbf{Lessons learned.}
\begin{enumerate}
\item \textbf{Validation design matters more than model tuning.} A validation set that shared the training period produced confident but wrong model choices; separating it in time changed the conclusion from ``the correction hurts'' to ``the correction helps the largest errors''.
\item \textbf{Physical constraints are cheap and effective.} Building in the requirement that the correction vanish at zero horizon fixed most of the short-horizon damage in ridge without any tuning.
\item \textbf{One summary statistic can mislead.} The same model is 12.5\% better by RMSE and 14\% worse by median; with heavy-tailed errors, which statistic matters depends on the application.
\end{enumerate}

\textbf{Proposed improvements,} in order of expected value: validate against precise ephemerides for a subset of objects; fit separate models or add gating by altitude regime, chosen on validation data; add forecast space weather as an input; implement a Runge--Kutta propagator (topic 7.4) as a numerical baseline, with a step-size convergence study; run the training-size and altitude-generalisation studies; and add explicit input-domain checks.
